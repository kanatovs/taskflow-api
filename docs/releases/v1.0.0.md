# TaskFlow API v1.0.0

TaskFlow is a backend REST API for collaborative project and task management.
Version 1.0.0 provides the following implemented capabilities.

These notes describe the original v1.0.0 release scope. Later changes are listed
in the [changelog](../../CHANGELOG.md).

## Highlights

- Registration with normalized unique email and bcrypt passwords, HS256 JWT
  login and authenticated current-user lookup.
- Project CRUD, atomic owner membership and owner/admin/member permissions.
- Task CRUD, current-member assignment, status transitions, priorities, nullable
  due dates and assignees, and comments with author/manager permissions.
- Project-scoped filters, literal text search, stable sorting and pagination.
- PostgreSQL persistence with four reversible migrations, constraints, indexes,
  context deadlines and transactional permission rechecks.
- Optional Redis project/task detail caching with TTL, invalidation, malformed
  value handling and PostgreSQL fallback during Redis outages.
- JSON envelopes/errors, request IDs, structured logs, bounded request bodies,
  health/readiness and graceful shutdown.
- Non-root Docker build, Compose development environment, unit/integration and
  smoke tests, GitHub Actions and validated OpenAPI documentation.

The [OpenAPI contract](../openapi.yaml) is version 1.0.0: 13 paths and 23 HTTP
operations. The database schema is version **4**, `dirty=false`. Release
preparation focused on documentation, verification and dependency hardening.
Redis is patched to 8.2.10 and all external container images are pinned by digest.

## Setup and verification

Follow [README](../../README.md) for PowerShell setup, environment variables,
Docker/migration commands and working request examples. See
[architecture and diagrams](../architecture.md), the [testing guide](../testing.md)
and [changelog](../../CHANGELOG.md) for details.

Automated checks cover formatting, vet, tests/build, empty-database migration
up/down/up and dirty rejection, real PostgreSQL/Redis integration, permissions,
cache invalidation, Redis outage/recovery, API startup and graceful shutdown.
OpenAPI structure and 41 examples are validated.

## Known limitations

- No refresh/revocation, password reset, email verification, rate limiter,
  invitations, owner transfer, frontend or deployment automation.
- Compose is a development environment with public/privileged credentials;
  deployment needs appropriate secrets, TLS and access controls.
- Redis details can remain stale within TTL after failed invalidation or an
  in-flight stale refill. Project writes serialize, offset pages can shift under
  writes, and text search has no full-text index.
- No license has been selected. No container-wide CVE scan or penetration test
  was performed; the credential-history scan supports selected patterns only.
- Release-time govulncheck found no reachable or imported-package vulnerabilities;
  its OpenPGP advisory concerned an unimported package in the bcrypt module.
